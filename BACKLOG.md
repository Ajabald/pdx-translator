# Бэклог

Задачи вне текущей версии. Порядок внутри секций — по отдаче на вложенный труд.

## Шаги публикации (когда решишь выкладывать)

Файлы готовы: `LICENSE` (GPL-3.0), `.gitignore`, `README.md` с английской
секцией, `pyproject.toml` (0.3.0), `ck3-translator.spec` (PyInstaller, onedir),
заготовка `.github/workflows/ci.yml`. Остаётся:

1. **Переименовать проект** — обсуждалось имя «PDX Translator» (пакет
   `ck3loc` → `pdxloc`, репозиторий `pdx-translator`): формат общий для всех
   игр Paradox, привязка к CK3 в названии сужает аудиторию. Делать одним
   шагом перед первым коммитом, чтобы история началась с нового имени.
   Не сделано сейчас, чтобы не ломать работающий инструмент.
2. `git init`, первый коммит, `gh repo create` — только вручную.
3. Иконка приложения (в `.spec` сейчас заглушка) и скриншоты для README.
4. ~~Проверить сборку~~ — **сделано 2026-08-02**: PyInstaller 6.21 на Python
   3.14.3, `dist\ck3-translator` весит 120 МБ (из них PySide6 93 МБ), плагины
   платформы Qt на месте, данных пользователя внутри нет. Собранный exe прошёл
   полное сканирование дерева BLA с верными числами. Осталось проверить запуск
   на машине без Python.
5. **Базы памяти в релиз не кладём.** Это чужая локализация (Paradox и авторов
   переводов); распространять её нельзя, а инструмент собирает базу из копии
   игры пользователя за секунды. В README это описано в разделе «Базы памяти
   переводов»; `.gitignore` исключает `Bdd/`, `Projects/`, `backups/` и все
   `*.ck3tm` / `*.ck3proj`.
6. Раздача: приватный репозиторий раздаётся только поимёнными приглашениями —
   режима «по ссылке» у GitHub нет. Для переводчиков нужен архив с `dist`,
   выложенный отдельно. Учесть GPL-3.0: получателям бинарника надо обеспечить
   доступ к исходникам той же версии.

## Критично для публичного релиза

Оценка ниши (август 2026): прямых аналогов класса ESP-ESM Translator в сцене
Paradox нет. Есть батч-конвертеры (ModTranslationHelper), наборы CLI-скриптов
(Paradox_localization_utils), примитивные GUI-обёртки над машинным переводом
(CK-3-Translator) и веб-платформа для команд (ParaTranz). Построчного рабочего
места переводчика с базой, статусами, памятью переводов и диффом версий —
ни у кого. Ниша свободна, но удержать её мешают четыре пробела:

1. **Английский UI** (i18n). Сейчас интерфейс только русский — это отсекает
   большую часть аудитории (китайские, испанские, французские команды
   переводчиков — самые активные). Механика: вынести строки в словарь
   (`core/i18n.py` или Qt Linguist `.ts`), переключатель языка в настройках,
   английский по умолчанию при системной локали != ru.
2. **Ванильная база CK3 в комплекте.** Моды копируют сотни строк из ванили,
   уже официально переведённых Paradox. Инструмент сборки базы появится в v3
   (M6), но нужно ещё собрать готовые `.ck3tm` и приложить к релизу
   (лицензионный вопрос: распространять базу или инструкцию «постройте из
   своей копии игры» — второе безопаснее).
3. **Машинный перевод** (DeepL / Claude API). Главная причина, по которой
   скачивают конкурентов. В v3 (M7) делается только каркас: интерфейс
   провайдера + экранирование CK3-тегов. Живые провайдеры — следующая версия.
4. **Другие игры Paradox** (Stellaris, HOI4, EU4, Victoria 3). Формат
   локализации тот же самый — расширение почти бесплатное, аудитория ×3-5.
   Нужно: настройка игры в проекте, специфичные наборы токенов для QA,
   тестовые данные для каждой игры.

## Функциональность (из паттернов ESP-ESM Translator)

- **Автоизвлечение терминов (кандидат в главную фичу).** Похожие строки уже
  ищутся целиком (`core/fuzzy.py`), но подсказки уровня «в базе есть
  Targaryen → Таргариен» пока нет. Замер на живом корпусе (AGOT + русификатор,
  51 651 пара) показал, что статистика совстречаемости (коэффициент Дайса)
  считается за 0.8 с и даёт 4024 кандидата, из них 1287 с уверенностью ≥ 0.60:
  `Winterfell → винтерфелл` 0.63, `Maester → мейстер` 0.65,
  `Lannister → ланнистер` 0.56, `Braavos → браавос` 0.54. Три известные
  проблемы: русские словоформы дробят счёт (`таргариен` / `таргариенов` —
  нужна группировка по основе), многословные термины требуют биграмм на
  русской стороне (`Kingsguard` → «Королевская гвардия» разваливается на два
  слова), шаблонный шум (`Valyrian → эссос` 0.63) лечится требованием отрыва
  от второго кандидата. Модель — «статистика предлагает, человек
  подтверждает»: список курируется в отдельном окне, подсветка терминов в поле
  оригинала делается теми же `ExtraSelections`, что и подсветка изменений
  оригинала в `gui/detail_pane.py`. Хранение — таблица рядом с глоссарием M7.
- **Импорт по одному файлу и предпросмотр построчно.** Команда «Загрузить
  перевод из мода…» уже есть (`core/loc_import.py`), но принимает дерево
  целиком: в окне показываются первые 20 изменений, выбрать отдельные строки
  или ограничить набор файлов нельзя (в `ImportOptions` для этого есть
  `only_files`, UI не сделан). У EET в окне *Import* есть ещё «Fast Import» и
  импорт в отдельную колонку для сравнения.
- **Скан перестаёт читать дерево перевода.** Сейчас `core/scanner.py` при
  каждом сканировании читает RU-файлы и заполняет ими пустые строки — удобно
  при заведении проекта, но это тот же импорт, только неявный. После появления
  явной команды имеет смысл оставить чтение только для первого скана. Тронет
  дифф-автомат и тесты `test_scanner_v3.py` (расхождения «база против диска»),
  поэтому отдельной задачей.
- **Пер-колоночные фильтры** с мини-языком EET: `!` — не содержит, `=` —
  точное совпадение, ` || ` / ` && ` — булевы связки, флаги «учитывать
  регистр» / «регулярное выражение».
- **История строки** с откатом: таблица `unit_history(unit_id, ru_text,
  changed_at)`, диалог «История строки» с возвратом к предыдущему переводу.
- **Трансформации текста** над выделением: первая буква заглавная, каждое
  слово с заглавной, срезать пробелы/переносы в начале/конце, добавить
  префикс/суффикс.
- **Матрицы замен** — именованные наборы «найти/заменить», применяемые пачкой
  в обе стороны (EET: Replace Matrix).
- **Ручной приоритет TM-баз** (в v3 приоритет фиксированный по типу базы).
- **Проверка длины строк** по лимитам игры (у Paradox нет жёстких лимитов, но
  есть практические — для интерфейсных элементов).
- **Предпросмотр разметки**: рендер `#bold`, цветов и иконок как в игре.

## Обновление мода: оставшиеся пробелы

Разбор целиком — в [ARCHITECTURE.md](ARCHITECTURE.md), раздел «Известные пробелы».

- **Сменить папку оригинала у существующего проекта.** `en_root` задаётся при
  создании и в интерфейсе не редактируется. Пока Steam обновляет мод на месте,
  это не мешает; помешает, если новую версию скачали отдельно. Нужен пункт
  «Проект → Сменить папку оригинала…» с проверкой, что в новой папке те же
  файлы, и предупреждением о числе строк, которые станут «удалёнными».
- **Вкладка «История оригинала».** Таблица `source_history` копится с v4, но в
  панели виден дифф только с последней редакцией. Данные и
  `unit_ops.source_history()` готовы, не хватает UI (часть M8).
- **Переименование ключа автором мода** сейчас выглядит как «старый удалён,
  новый добавлен»: перевод уходит в архив, новая строка заводится пустой.
  Спасает память переводов, но можно ловить прямо в сводке сканирования —
  сопоставлять исчезнувшие и появившиеся ключи по одинаковому тексту оригинала.
