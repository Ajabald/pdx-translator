# Приёмочное тестирование

Юнит-тесты проверяют, что код делает задуманное. Приёмка проверяет, что
задуманное и есть то, что обещано переводчику.

Правило: **возможность считается принятой, когда она названа в README и
проверена на живых данных.** Это то же правило, которым от протухания
защищается [BACKLOG.md](BACKLOG.md), только применённое к проверке.

## Замер 0.1.2 (2026-08-22)

| Прогон | Результат |
|---|---|
| Без живых деревьев (`-m "not realdata"`) | 1294 прошли, 2 пропущены, 46 отсечены, 22 с |
| С деревом мода (по умолчанию) | 1315 прошли, 27 пропущены, 26 с |
| **С деревьями четырёх игр** | **1339 прошли, 3 пропущены, 93 с** |
| `ruff check .` | чисто |

Три пропуска на полном прогоне, и все три — по замыслу, а не от нехватки данных:

* `test_secrets` проверяет поведение **без** DPAPI, поэтому на Windows и
  пропускается: здесь ключ шифруется по-настоящему, а этот тест про запасной
  путь для систем, где шифровать нечем;
* `test_qa_rules_examples` пропускает правило `inconsistent` — оно смотрит на
  весь проект сразу, и парой строк-примеров его не показать;
* `test_qa_glued_markup` — случай, которого нет в дереве agoot; тот же случай
  закрыт на синтетике.

## Этап A. Автоматическая приёмка

Основной приёмочный прогон — это полный прогон со всеми живыми деревьями, а не
`-m "not realdata"`:

```
QT_QPA_PLATFORM=offscreen
PDXT_REALDATA_HOI4=<…>/Hearts of Iron IV/localisation
PDXT_REALDATA_STELLARIS=<…>/Stellaris/localisation
PDXT_REALDATA_CK2=<…>/Crusader Kings II/localisation
.venv\Scripts\python.exe -m pytest -q -rs
```

`PDXT_REALDATA` можно не задавать, если дерево мода лежит в папке над
репозиторием: `tests/conftest.py` ищет его там по умолчанию.

## Этап C. Ручные сценарии

Автотесты не нажимают кнопок. Сценарии идут по трём путям из
[ARCHITECTURE.md](ARCHITECTURE.md) и прогоняются на копии живого проекта.

### C1. Перевод мода с нуля

1. Создать проект: игра, папка оригинала, языки. **Папку перевода оставить
   пустой** — у мода, который есть только по-английски, её и нет.
2. F5. Строки из одной разметки ушли в «Игнорируется».
3. Правка в ячейке и в нижней панели; `Ctrl+Enter` идёт к следующей
   непереведённой, `F7` подставляет из памяти, `F8` — оригинал.
4. `Ctrl+E`: папка спрошена один раз (поле пустое, запись без неё не идёт);
   UTF-8 с BOM, верный заголовок языка, порядок строк и комментарии сохранены,
   неизменённые файлы не переписаны, прежние версии легли в `backups/` **вне**
   дерева локализации.
5. Второй `Ctrl+E` папку уже не спрашивает: выбранная запомнилась и стала
   папкой перевода проекта.
6. «Проект → Сменить папку перевода…»: предпросмотр говорит, сколько файлов
   перевода в выбранной папке нашлось; пустое поле оставляет проект без папки.
7. `Ctrl+Z` откатывает пакетную правку.

### C2. Есть готовый перевод

1. «Файл → Загрузить перевод из мода…» на чужом переводе этого мода.
2. Правила и предпросмотр показаны **до** записи; пакет откатывается одним
   `Ctrl+Z`.
3. Собрать базу памяти из ванили, включить в шапке окна, убедиться, что
   подсказки появились.
4. `Ctrl+Shift+F` — «как переводили это раньше» по выделенному куску.

### C3. Обновился оригинал

1. Подменить папку оригинала на новую редакцию, F5.
2. Сводка разделила правки на смысловые и косметические, колонка «Δ» на месте,
   изменённые слова подсвечены в поле оригинала.
3. Косметические подтверждаются пачкой и откатываются `Ctrl+Z`.
4. Переводы исчезнувших ключей — в «Проект → Архив старых переводов…».

### C4. Глоссарий

1. `Shift+F9` → «Кандидаты» → «Найти термины». Прогресс идёт, окно не
   подмерзает, «Остановить» срабатывает, закрытие посреди счёта спрашивает.
2. Принять термин, отклонить шум. **Повторить прогон — отклонённый не вернулся.**
3. Термин подсвечен в поле оригинала, наведение показывает перевод.
4. **Устаревшая строка: подсветка изменений и подсветка термина видны разом.**
5. Снять «подсвечивать термины»: ушли термины, дифф остался.
6. Снять «только имена собственные» — появляются общие слова; вернуть.

### C5. Проверки и обмен

1. `F6` — отчёт по проекту, `Shift+F6` — окно правил.
2. Смена пресета двигает число замечаний в ожидаемую сторону.
3. Своё правило каждого из шести видов; битое выражение гасит **только своё**
   правило, а не весь проход.
4. «Не ошибка» убирает срабатывание; вкладка помеченных возвращает.
5. Экспорт `.pdxqa` → импорт в другой проект: набор, дельта и свои правила
   на месте.

### C6. Интерфейс и языки

1. Смена языка в «Параметрах» применяется на лету, все три языка.
2. Смена темы на лету: поле оригинала, дерево файлов, записи подключённых баз.
3. У каждой кнопки панели есть пункт меню с той же клавишей.
4. Сортировка: три клика возвращают исходный порядок; на «!» второй клик
   оставляет только строки с замечаниями.

### C7. Управление проектами

1. Показать в файловом менеджере, убрать из списка (`Delete`), удалить с файлом
   (`Shift+Delete`) — **в корзину**.
2. Файл, не влезающий в квоту корзины, даёт предупреждение со списком.
3. Проект в чужом загоне игры при открытии предлагает перенести себя.

### C8. Мастер первого запуска

Показывается **один раз за жизнь установки**, поэтому проверяется так: снять
копию ветки целиком (`reg export HKCU\Software\pdx-translator`), убрать из
`…\general` запись `first_run_done` и поставить там же `reopen_last=false` —
иначе поверх мастера откроется последний проект, а его открытие пишет в файл
проекта отметку времени. Обе записи вернуть после прогона.

Запускать **из исходников или из свежей сборки**: ярлык «PDX Translator» в меню
«Пуск» может вести на прошлую установку, и проверишь не то.

1. Шаг «Язык интерфейса»: в списке стоит тот язык, **на котором нарисовано
   окно**, а не язык системы. Разойтись они могут не в лаборатории: куст
   прежнего имени `ck3-translator` приносит язык через `adopt_previous_settings`,
   а `first_run_done` в новом кусте отсутствует по определению.
2. Шаг «Память переводов»: текст называет настоящее число найденных баз, а не
   «баз пока нет».
3. «Собрать базу…» **открывает окно памяти** — с одной вкладкой «Сборка базы»,
   потому что проекта ещё нет. Это тот самый отказ 0.1.0: окно требовало
   открытого проекта и падало прямо в слоте кнопки, а собранное приложение идёт
   без консоли — наружу не выходило ни строчки.
4. Закрыть окно сборки: мастер остался на месте, текст шага перечитан.
5. «Пропустить» и крестик засчитываются ответом — второй запуск идёт мимо.

Шаги 1 и 3 — дефекты, с которыми пришли жалобы на 0.1.0. Оба проверены вживую
на 0.1.2 (2026-08-20): окно сборки открывается, мастер показан на языке, который
и предлагает.

## Этап D. Сборка и машина без Python

```
.venv\Scripts\pyinstaller.exe pdx-translator.spec
```

1. `pdx-translator.exe` запускается двойным кликом, без консоли.
2. Рядом создаются `Bdd` и `Projects`; данных пользователя внутри сборки нет.
3. **Лицензии на месте:** рядом с exe лежат `LICENSE` (GPL-3.0),
   `LICENSE.LGPL-3.0.txt` и `THIRD-PARTY.md`. Это не формальность: PyInstaller
   кладёт внутрь архива Qt (93 МБ из 120), то есть мы его распространяем, а
   текста LGPL в колесе PySide6 нет — его скачивают руками
   (<https://www.gnu.org/licenses/lgpl-3.0.txt>). Разбор — в
   [THIRD-PARTY.md](THIRD-PARTY.md).
4. «Справка → О программе» показывает версию, copyright, отсутствие гарантий и
   упоминание Qt под LGPL.
5. Иконка приложения на месте, у exe заполнены свойства.
6. Плагины платформы Qt на месте — окно рисуется.
7. Интерфейс переключается на русский и китайский: `.qm` доехали внутрь сборки.
8. Иконки панели свои, а не стандартные иконки стиля Qt.
9. Полное сканирование живого дерева даёт **те же числа**, что из исходников.
10. Перенести папку на машину **без Python** и повторить пункты 1, 6, 9.
11. Запустить из папки на съёмном носителе — режим переносимый.

## Этап E. Чего приёмкой не закрыть

- **Живой прогон машинного перевода на платном ключе.** Все тесты на заглушках,
  ни один не открывает сокет.
- **Раздача исходников получателям бинарника (GPL-3.0)** — обязательство, а не
  поведение программы.
- **Терминология китайского интерфейса.** С носителем не сверена. Из 969 строк
  459 в десяти контекстах (`Actions`, `Exporter`, `Glossary`, `MainWindow`,
  `ParadoxCsv`, `QaRules`, `Relocate`, `RootDialog`, `RulesWindow`,
  `StartScreen`) помечены `unfinished` — это машинный перевод, которого человек
  не читал. Проверено то, что проверяется без носителя: плейсхолдеры целы,
  термины совпадают с уже вычитанными окнами, отрицания не потеряны, латинские
  глифы колонок не тронуты. Пометку возвращает тот, кто перечитает контекст.

## Критерии приёмки

1. Полный прогон этапа A — ноль падений; пропусков три, и каждый объяснён выше.
   Без `PDXT_REALDATA_CK2_RU` их семь: четыре добавляет пара «ваниль CK2 ↔
   русификатор».
2. `ruff check .` — чисто.
3. Сценарии этапа C пройдены на живом проекте.
4. Чек-лист этапа D пройден, включая машину без Python.
5. Иконка, `version_file`, диагностический лог и скриншоты в README — сделаны.
6. Всё закоммичено, тег выставлен, CI собрал архив и приложил к релизу.

## Принятые риски

Эти пропуски закрываются только данными, которых нет под рукой. Признаны
**не блокирующими** (решение 2026-08-18, пересверено 2026-08-22):

| Пропуск | Почему приемлемо |
|---|---|
| 4× CK2 «оригинал ↔ перевод» (`PDXT_REALDATA_CK2_RU`) | Разбор CSV и перезапись оригинала проверены на живой ваниле CK2; не проверена только пара с русификатором. На машине автора русификатор распакован, и в замере 2026-08-22 эти четыре теста прошли — риск остаётся для чужой машины |
| 1× `test_qa_glued_markup` на большом проекте | Дублирует закрытое на дереве мода; сам проект (366 МБ) в рабочей папке отсутствует |

Ещё два пропуска **намеренные и постоянные**: правило, которому нужен весь
проект (парой строк его не показать), и поведение хранилища ключей без DPAPI
(проверяется на не-Windows).
