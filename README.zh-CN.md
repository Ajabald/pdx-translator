# PDX Translator

*[In English](README.md) · [По-русски](README.ru.md)*

一款用于翻译 Paradox 游戏模组本地化的离线桌面工具 —— 它是译者的工作台，而不是
批量转换器：带状态的字符串表格、翻译记忆库、术语表、模组版本比对，以及可配置的
标记检查。

支持系列中的八款游戏，此外还可以用任意名称添加自定义游戏。游戏和语言在创建项目
时选择。

> 版本 0.1.2。界面提供英语、俄语和简体中文 —— 在「文件 → 首选项」中选择语言，
> 选择后立即生效。

## 功能

- **一个项目就是一个文件**（`*.pdxproj`），其中保存字符串、译文、记忆库和存档。
  放在哪里都行，可以复制，也可以交给别人。在「翻译项目」界面上可以在资源管理器
  中显示它、从列表中移除（`Delete`），或者连同文件一起删除（`Shift+Delete`）——
  删除时文件会移入回收站，所以点错了还能找回来。
- **系列中的八款游戏**：Crusader Kings III、Crusader Kings II、Europa
  Universalis IV、Europa Universalis V、Hearts of Iron IV、Stellaris、
  Victoria 3、Imperator: Rome —— 如果格式相同但名称不在列表中，还可以用任意名称
  添加自定义游戏。Crusader Kings II 使用较早的 CSV 格式，识别依据是数据本身，而
  不是文件名。每款游戏都带有自己的一套语言文件夹，因此你选不到该游戏没有的语言。
  项目和记忆库数据库分游戏存放（`Projects\CK3`、`Bdd\CK3`）：CK3 的原版字符串没
  有理由推荐给 Victoria 3 的译者。
- **模组更新**：重新扫描后可以看到作者改了什么 —— 一份区分实质修改与表面修改的
  汇总、表格中的「Δ」列、直接在原文字段里高亮的改动词语，以及该行历次修订的历史。
  表面修改（标点、大小写、空白）可以用一个操作批量确认，任何操作都可以撤销
  （Ctrl+Z）。
- **翻译记忆库**，可挂接 `Bdd` 文件夹中的数据库（`*.pdxtm`）：游戏的原版本地化、
  上游模组的译文、其他项目的导出。匹配到的内容会自动填入。你自己的条目可以浏览、
  编辑和删除（「工具 → 翻译记忆库…」，F9 ——「条目」标签页）。
- **相似字符串，而不只是完全匹配。** 建议面板会显示只差一两个词的条目，附带相似度
  和高亮的差异 —— 在模组之上翻译子模组时，完全匹配几乎没有，近似匹配却很多。此外
  还有「以前是怎么翻译的…」搜索（Ctrl+Shift+F），针对原文中选中的片段：想知道某个
  名称或某种说法此前是怎么处理的，就用它。索引存放在数据库内部；早期版本构建的
  数据库可以在记忆库窗口的「数据库」标签页上用按钮补建索引。
- **由统计给出、由你确认的术语表。**「工具 → 术语表…」（Shift+F9）在翻译记忆库
  上统计词语共现 —— 既包括项目自身的，也包括每个已挂接的数据库 —— 并给出诸如
  `Maester → мейстер` 的词对，附带置信度和支撑它的对数。俄语词形按词干归并，
  因此 `Таргариен` 和 `Таргариенов` 会累加，而不是各算各的；两个词组成的术语同样
  能捕捉到。没有任何内容会自行进入译文：每个候选都由你接受或拒绝，被拒绝的下次
  不再出现。已接受的术语会在原文中高亮 —— 悬停即可看到它的译法。参见
  [术语表](#术语表)。
- **机器翻译**提供六条路径 —— DeepL、Claude、OpenAI、Google Cloud Translation、
  Yandex Translate，以及在没有密钥时手动通过任意网页翻译器。标记会对服务隐藏并在
  之后还原，结果获得单独的「机器翻译（未校对）」状态，并且一定会经过质量检查。
  参见[机器翻译](#机器翻译)。
- **编辑器**：在单元格中或在底部面板中编辑，CK3 标记高亮（`[GetTrait…]`、
  `$VAR$`、`#bold…#!`、`@gold!`），带进度的文件树，批量操作，不区分大小写的搜索。
- **一个工作台**：常用操作的工具栏，顶栏中始终可见的项目语言和已挂接的记忆库数据库
  （在那里一键开关数据库），可即时切换的浅色和深色主题。每个工具栏按钮都有同名同
  快捷键的菜单项，因此一切既能用鼠标到达，也能用键盘到达；设置在「文件 → 首选项…」
  中。
- **列排序**：点击表头为升序，再点为降序，第三次回到原始顺序（文件与行号）。同一
  时刻只有一列生效。在「!」列上，第二次点击不是反转顺序，而是只留下有问题的行 ——
  与「仅有问题的行」复选框和「筛选 → 仅有问题的行」是同一个筛选。
- **可调的质量检查**：问题显示在行旁边的「!」列中 —— 丢失的 `$…$` 变量和 `@…!`
  图标、与原文不一致的标签、对不上的 `\n` 换行、双空格和边缘空格、替换符前缺少的
  空格（`house[GetPlayer…]` 在游戏里会渲染成「houseStark」）、对英语系动词的直译
  （`tend to be [GetTrait…]` 会渲染成「tend to be Loyalty」，因为 CK3 用名词命名
  特质）、不成对的引号、同一原文出现不同译文。任何规则都可以关闭、降级为警告或者
  给予宽松度；自定义规则有六种类型，整套设置可以作为单个文件交给另一位译者。参见
  [配置检查](#配置检查)。误报可以标记为「不是错误」，之后不再出现；整个项目的报告
  是 F6。
- **从模组载入译文**是一条单独的命令（「文件 → 从模组载入译文…」）：可以取用别人
  对这个模组的翻译，也可以取回你自己直接在文件里做的修改。规则（仅填空行还是覆盖、
  是否跳过译文与原文相同的行）会在写入前连同预览一起展示，整批操作用一次 Ctrl+Z
  撤销。
- **将译文写入模组**，采用游戏的格式：文件名和文件头带上正确的语言，UTF-8 带 BOM，
  保留原有顺序和注释，未改动的文件不会被重写。模组文件夹会与导入译文的文件夹分开
  记在项目里，被覆盖文件的旧版本进入 `backups` —— 放在本地化目录树之外，否则游戏
  会把副本和正式文件一起读进去。

## 安装与运行

已构建的版本（Windows）—— 解压压缩包并运行 `pdx-translator.exe`。无需 Python；
`Bdd` 和 `Projects` 文件夹会创建在可执行文件旁边，因此它可以放在 U 盘上运行。

从源码运行（Python 3.11 或更新版本）：

```
py -3.11 -m venv .venv
.venv\Scripts\python.exe -m pip install -e .
.venv\Scripts\python.exe -m pdxloc
```

也可以双击 `run.bat`。构建便携版：
`.venv\Scripts\pyinstaller.exe pdx-translator.spec` —— 结果在 `dist` 中。

## 快速上手

1. **创建项目**：选择游戏、原文文件夹（`*_l_english.yml` 文件所在处）、译文文件夹
   和语言。
2. **F5** —— 扫描：字符串进入表格。
3. 翻译：双击译文单元格，或者在底部面板中编辑。`Ctrl+Enter` 保存并转到下一条未翻译
   的行。
4. **Ctrl+E** —— 将译文写入模组：选择模组文件夹。这个选择会记在项目里，下次直接
   提供。

## 翻译记忆库数据库

模组会从原版游戏以及它所依赖的模组中复制成百上千条字符串，因此第一件值得做的事就是
构建数据库：

- **原版**：「翻译记忆库 → 构建数据库」，文件夹
  `…\Crusader Kings III\game\localization\english` 和
  `…\localization\<你的语言>`，类型选「游戏数据库（原版本地化）」；
- **上游模组**（如果你翻译的是子模组）：该模组自己的本地化文件夹，以及它的译文
  文件夹（通常是创意工坊里单独的一个模组，文件位于 `…\localization\<语言>`），
  类型选「导入他人的译文」。

应用程序**不附带**现成的数据库：那些本地化属于 Paradox 和各译文的作者。工具会在
几秒钟内用你自己的游戏副本和你自己订阅的内容构建它们，这也是唯一合法的使用方式。
构建好的数据库在同一窗口的「数据库」标签页中启用，或者直接在窗口顶栏中启用。

## 术语表

模组会自造名称，而术语表的全部意义就在于：同一个名称在第 1 页和第 400 页上译法一致。
手工整理这份清单是这项工作中最枯燥的一半，所以「工具 → 术语表…」（Shift+F9）会从你
已经翻译过的内容里把它提出来。

- **候选**在翻译记忆库上用共现的 Dice 系数统计得出：原文中的某个词和译文中的某个词
  总是出现在同一些行里，那它们多半就是彼此的译法。每个候选都带有置信度和它被看到的
  对数，因此这个数字依据何在一目了然。
- **统计只负责建议。** 候选在你接受之前不会改变任何地方，被拒绝的候选下次运行时不再
  提供 —— 你的「否」同样是数据。
- **已接受的术语会在原文字段中高亮**；悬停即可看到已接受的译法。这个高亮与已过时行
  上的改动高亮可以共存，两者都可以用各自的复选框关掉。
- **术语也可以手工录入**，在「术语」标签页上 —— 没人提议过的术语无需确认。
- **「仅限专有名词」**默认开启：只提供在短语中间仍以大写开头的词。正是这一点把
  `Targaryen` 和 `Now` 区分开来 —— 两者都会以大写形式出现，但只有其中一个会出现在
  句子中间。关掉它，列表里就会混进「Now → теперь」这类正确却无用的词对。

统计在三件事上胜过朴素的词频计数：俄语词形按词干归并（`Таргариен` 和
`Таргариенов` 累加而不是各算各的）、能找到由两个词组成的译法（`Kingsguard` →
「Королевская гвардия」），以及丢弃仅仅是结伴出现的词 —— 真正的术语会以明显的优势
赢得它的译法，模板噪声则不会。

## 机器翻译

服务在「文件 → 首选项 → 机器翻译」中选择。Ctrl+M 翻译一行，「工具 → 机器翻译…」
翻译一批。

| 路径 | 是否需要密钥 |
|---|---|
| DeepL | 需要 |
| Claude | 需要 |
| OpenAI | 需要 |
| Google Cloud Translation | 需要 |
| Yandex Translate | 需要（外加一个目录 ID） |
| 手动，通过网页翻译器 | 不需要 |
| 关闭 | —— |

手动路径是给没有密钥的人准备的：应用程序把这些行连同编号分隔符一起整理出来，你把
这段文本粘贴到任意网页翻译器里，再把结果带回来。

这里要紧的是：

- **标记会对服务隐藏。** 每个标签都会替换成占位符，并在翻译后还原；丢失的占位符会
  进入报告，而不是进入模组文件。
- **一批要么整批应用，要么一条都不应用。** 如果服务的回答无法解析，这一批里没有任何
  一行会被写入 —— 错位一格就会悄悄毁掉整个段落。
- **结果标记为「机器翻译（未校对）」。** 这样的译文不会进入翻译记忆库，没有明确勾选
  就不会写进模组，一定会经过质量检查，并且在有人动过这一行的那一刻就不再算机器翻译。
- **密钥保存在 Windows 设置中，由 DPAPI 保护**（`CryptProtectData`）。这能让它避开
  注册表里窥探的目光，也让把注册表项复制到另一台机器变得毫无用处，但它**不能**防住
  以你自己的账户运行的程序。付费服务按字符计费 —— 批量大小和请求之间的间隔在同一处
  配置。

## 配置检查

「检查 → 配置检查…」（Shift+F6）。什么算作错误，取决于模组、语言和工作阶段，因此
规则集不是常量：

- **17 条内置规则。** 每一条都可以设置是否开启、严重程度（错误还是警告）以及它的
  宽松度 —— 例如，哪些用于变格的包装调用不应算作括号不匹配。
- **自定义规则**共六种类型：词元多重集比较、词元计数、针对译文的正则表达式、针对
  原文与译文这一对的正则表达式、字符配平，以及禁用字符。自定义规则可以完整配置，
  包括提示语文本和示例。
- **七套现成的规则集**：「严格」「仅致命问题」「自定义」，以及每款游戏与语言各一套
  ——「CK3 · 俄语」「HOI4 · 俄语」「CK2 · 俄语」「Stellaris · 俄语」。这个差别不是
  装饰：在一份 136 113 行的真实译文上，严格集报出 41 713 个问题，内置默认值报出
  37 040 个，「CK3 · 俄语」12 591 个，「仅致命问题」11 404 个（测于 2026-08-10）。
  与你的项目相配的那一套 —— 按游戏和译文语言选出 —— 会排在列表最前面，并标注
  「推荐用于本项目」；没有打开项目时不推荐任何一套。
- **三个层次**：内置值、应用程序旁边的全局 `qa_rules.json`，以及保存在项目自身内部
  的设置。每一层只保存差异，因此更新应用程序不会抹掉你的配置。
- **共享一套设置** —— 同一窗口中的「导入…」和「导出…」按钮，一个 `.pdxqa` 文件。
  团队就是这样就「什么算错误」达成一致的。该文件自成一体：选定的规则集、相对内置
  规则的差异，以及完整的自定义规则。

## 行状态

| 状态 | 颜色 | 含义 |
|---|---|---|
| 未翻译 | 红色 | 没有译文 |
| 机器翻译（未校对） | 沙色 | 由服务翻译，人还没看过 |
| 自动（来自记忆库） | 黄色 | 从翻译记忆库填入，需要复核 |
| 已翻译 | 绿色 | 译文已保存 |
| 已校对 | 深绿色 | 译文已由人手确认 |
| 已过时 | 橙色 | 译完之后原文发生了变化（会显示差异） |
| 已忽略 | 灰蓝色 | 没有可翻译的内容（比如整行都是裸标签） |
| 自定义 | 紫色 | 你自己的标记 |

百分比统计的是已翻译和已校对的行，分母是除已忽略之外的全部行。原文中消失的键所对应
的译文不会丢失 —— 它们会移入「项目 → 旧译文存档…」。

## 文件布局

```
pdx-translator/
├─ Projects/       项目（*.pdxproj）—— 一个模组一个文件，一款游戏一个文件夹
│  └─ CK3/
├─ Bdd/            翻译记忆库数据库（*.pdxtm）—— 同样按游戏分开
│  └─ CK3/
├─ backups/        写入模组时被覆盖的文件的旧版本
│                  （快照以时间命名；你放在那里的其他东西不会被动）
├─ qa_rules.json   全局检查配置
├─ pdx-translator.log   诊断日志 —— 报告缺陷时请附上它
└─ pdx-translator.exe
```

这是便携版的布局。从源码运行时布局相同，只是没有 `.exe`：用 `run.bat` 启动，它是
`.venv\Scripts\pythonw.exe -m pdxloc` 的快捷方式。

真正的依据是项目文件，而不是 yml。在 yml 文件里手工做的修改会在重新扫描时被读入，
但发生冲突时以项目为准（扫描报告会列出这类情况）。

## 命令行

```
python -m pdxloc --project Projects\Mod.pdxproj --scan
python -m pdxloc --project Projects\New.pdxproj --create "名称" "path\english" "path\russian"
```

## 开发

```
.venv\Scripts\python.exe -m pip install --group dev
.venv\Scripts\python.exe -m pytest -m "not realdata"
```

标记为 `realdata` 的测试针对真实的本地化目录树运行；路径来自 `PDXT_REALDATA` 变量，
它们在 CI 中被排除。GUI 测试无需屏幕即可运行 —— `QT_QPA_PLATFORM=offscreen`。

修改界面字符串之后，请重新构建翻译：
`.venv\Scripts\python.exe tools\i18n.py all`。

构建便携版：`pyinstaller pdx-translator.spec`。
